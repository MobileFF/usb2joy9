# usb2joy9 — USB ジョイスティック → MSX / メガドライブ 9ピン変換

USB gamepad/keyboard to 9-pin joystick adapter for MSX and Mega Drive, using Raspberry Pi Pico (RP2040) USB host.

ファームウェアは接続先ごとに 2 種類あります: **usb2msxjoy** (MSX) / **usb2mdjoy** (メガドライブ 3ボタン)。

Raspberry Pi Pico (RP2040) / RP2040-Zero のネイティブ USB をホストとして使い、
USB ゲームパッド・USB キーボードの入力を MSX のジョイスティック信号、または
メガドライブの 3ボタンパッド信号 (MD 専用機、[後述](#メガドライブ専用機-usb2mdjoy)) に変換します。

> 当初は UIAPduino (CH32V003) を検討しましたが、CH32V003 は USB ホストになれない
> (rv003usb はデバイス専用・Low-Speed のみ) ため、USB ホスト内蔵の Pico に変更しています。

## 対応デバイス

- 汎用 HID ゲームパッド / ジョイスティック (X/Y 軸・ハットスイッチ・D-pad・ボタン1〜16 を自動解析)
  - 例: DragonRise 系の安価なパッド、DualShock 4、8BitDo (D-input モード) など
- USB キーボード (ブートプロトコル): 矢印 / テンキー 8・2・4・6 = 方向、
  Space・Z = ボタン1、X・M = ボタン2、C = ボタン3、Enter = ボタン10 (各ボタンの動作は割り当て設定に従う)
- USB ハブ経由で複数接続可 (入力は OR で合成)
- **非対応**: Xbox 360 / XInput 専用パッド (HID ではないため)

## ボタン割り当て

ボタン1〜16 それぞれに動作を割り当てられます。設定は Pico のフラッシュ末尾 (0x101FF000 からの 4KB) に置き、
起動時に読み込みます。設定がない・壊れている・別機種用のときは既定値で動きます。

| 動作 | MSX | MD |
|---|---|---|
| トリガA / A、トリガB / B | ○ | ○ |
| C、スタート | | ○ |
| 連射A / 連射B | ○ | ○ |
| 連射C | | ○ |
| 上下同時押し、左右同時押し | ○ | ○ |
| 上 / 下 / 左 / 右 | ○ | ○ |

- 既定値 (MSX): ボタン1 = トリガA、2 = トリガB、3 = 連射A、4 = 連射B
- 既定値 (MD): ボタン1 = A、2 = B、3 = C、10 = スタート
- スティック / 十字キーの上下・左右同時入力は、既定では打ち消します (誤動作するソフトがあるため)。
  ボタンに割り当てた「上下同時押し」「左右同時押し」は打ち消されません。
- 連射速度は 1〜30Hz (既定 15Hz)。
- ボタン番号はパッドごとに違います (DS4 なら 1=□ 2=× 3=○ 4=△ 10=OPTIONS)。
  押したボタンの番号は UART ログに `button N` と表示されます。

### 設定ツール (tools/config_gui)

Python 3 標準の tkinter だけで動きます (追加インストール不要)。

```sh
python3 tools/config_gui/config_gui.py
```

1. 接続先 (MSX / メガドライブ)、連射速度、各ボタンの動作を選ぶ
2. Pico の BOOTSEL を押しながら PC につなぐ
3. 「Pico に書き込み」を押す (RPI-RP2 ドライブを探して `config.uf2` をコピーします)

設定の UF2 は**設定データだけ**で、ファームウェアは含みません。設定領域だけを書き換えるので、ファームウェアはそのまま残ります。
逆にファームウェアを書き直しても設定は消えません。

- ボード (Pico / RP2040-Zero) や出力方式 (FXMA108 など) に関係なく、同じ設定 UF2 を使えます。接続先 (MSX / メガドライブ) だけはファームウェアと合わせてください (違うと無視され、既定値で動きます)。
- ボタン割り当て設定に対応したファームウェアを先に書き込んでおく必要があります。
- 「設定 UF2 書き出し」で保存したファイルを、RPI-RP2 ドライブに手動でコピーしても同じです。
- 「JSON 保存」「開く」で設定を保存・再編集できます (.json / .uf2 を開けます)。
- `picotool` がインストールされていれば「Pico から読み込み」で今の設定を読み出せます。
- コマンドラインでも変換できます: `python3 tools/config_gui/u2jconfig.py my.json -o config.uf2`

## 配線

RP2040 の GPIO は 5V トレラントではありません。MSX 側の入力は 5V にプルアップされているので、
**直結せず、必ずレベル変換を入れます。** 動作確認済みなのは FXMA108 です。

### FXMA108 (動作確認済み・推奨)

FXMA108 だけで、ダイオードなどの追加回路なしに MSX 実機で動作を確認しています (2026-10-20、Raspberry Pi Pico)。
その後ボタン割り当て設定を追加した版は、出力部分の動作は同じですが実機では再確認していません。

```
Pico                FXMA108                       MSX 9pin
GP2〜GP7 ───────── A0〜A5 ⇔ B0〜B5 ────────────── 1,2,3,4,6,7 (上と同じ順)
GP8  ──────────── /OE
3V3(OUT) ──────── VCCA
VBUS (40番ピン) ── VCCB ────────────────────────── 5  +5V
GND  ──────────── GND ─────────────────────────── 9  GND
                  A6,A7 / B6,B7 は未接続
```

- `cmake -DOUT_MODE=2` でビルドします (`firmware/MSX/usb2msxjoy_pico_fxma108.uf2`)。
  Pico 側は「押下 = L、離す = H」の push-pull で駆動し、GP8 で /OE を L にして有効にします。
- /OE は **L で有効**です。データシートでは、電源投入中に無効にしておくために /OE と VCCA の間へプルアップ抵抗 (10kΩ 程度) を入れることが推奨されています。
- 動作確認には秋月電子の FXMA108 変換モジュール [AE-LLCNV8-DIP20](https://akizukidenshi.com/catalog/g/g117062/) を使いました。
  このモジュールには VCCA・VCCB のパスコン (各 0.1µF) と /OE のプルアップ抵抗 (10kΩ、VA 側へ) が載っているので、
  **外付けのパスコン・プルアップ抵抗は不要**です (回路図の C1・C2・R1 に当たる部品)。
  モジュールのピン配置: 1=VA、2〜9=A0〜A7、10=GND、11=/OE、12〜19=B7〜B0、20=VB (300mil 幅の DIP20 相当)。
- FXMA108 は内蔵プルアップではなくバスホールド (標準 100µA 程度) で状態を保持するので、外付けのプルアップ/プルダウン抵抗は付けないでください。
  MSX 本体側のプルアップが強い機種ではバスホールドが負けて L を保持できない可能性が理論上はあります。別の機種で動かないときは、74LVC07A かダイオードを試してください。
- オートディレクション型なので、FXMA108 から MSX までの配線は短くしてください。

### 74LVC07A (6回路のオープンドレインバッファ。入出力とも 5V トレラント、実機未確認)

```
Pico                74LVC07A (VCC=3V3)          MSX 9pin (メス側を見て)
GP2  ──────────── 1A → 1Y ──────────────────── 1  上
GP3  ──────────── 2A → 2Y ──────────────────── 2  下
GP4  ──────────── 3A → 3Y ──────────────────── 3  左
GP5  ──────────── 4A → 4Y ──────────────────── 4  右
GP6  ──────────── 5A → 5Y ──────────────────── 6  トリガA
GP7  ──────────── 6A → 6Y ──────────────────── 7  トリガB
3V3(OUT) ──────── VCC
GND  ──────────── GND ──────────────────────── 9  GND
VBUS (40番ピン) ─────────────────────────────── 5  +5V
                                                8  ストローブ (未接続)
```

- 押したときは出力が L (GND に落ちる)、離したときは Hi-Z になり、本物のスイッチと同じ動作になります。
- 74LVC07A が手に入らないときは、1本ごとに NPN トランジスタ (2SC1815 など、ベース抵抗 4.7kΩ)
  や N-ch MOSFET (2N7000 など) で GND に落とす回路でも動きます。この場合は論理が反転するので、
  `cmake -DOUT_MODE=1` でビルドしてください。

### ショットキーダイオード (部品が手元にない場合、実機未確認)

```
Pico GPn ──|<── MSX ピン      (ダイオードのカソード(帯)を Pico 側、アノードを MSX 側)
```

- GP2〜GP7 それぞれに BAT43 / 1N5819 などのショットキーダイオードを 1 本ずつ入れます。ビルドは標準 (`OUT_MODE=0`) のままです。
- 押下時は Pico が L を出してダイオード越しに MSX の線を L に引き、離したときは Pico が H (3.3V) を出してダイオードが逆バイアスになり、MSX の線は MSX 側のプルアップで H になります。
- MSX 側がトリガ線 (6・7番ピン) を L に引いても、ダイオードが逆向きになるので出力同士はぶつかりません。
- MSX 側にプルアップがない機種では、H がダイオードの順方向分だけ下がった約 3V になりますが、TTL 入力なら H として読めます。

### 電源

- MSX の 5 番ピン (+5V) は Pico の **VBUS (40番ピン)** につなぎます。Pico 本体と USB コネクタの先の
  パッドの両方に電源が届きます (micro-USB の OTG 変換アダプタでパッドを接続します)。
- **VSYS (39番ピン) につないではいけません。** Pico 本体は動きますが、VBUS → VSYS 間のダイオードで止められて
  USB コネクタ側には 5V が出ないため、パッドもキーボードも認識されません (実際にこれで認識されなかった)。
- MSX のジョイスティックポートから取れる電流は少ない (規格上 50mA 程度) ため、消費電流の大きいパッドや
  ハブを使う場合は、外部の 5V を VBUS に入れ、MSX の 5 番ピンはつながないでください。
- **MSX につないだまま PC の USB をつながないでください** (VBUS で電源同士がぶつかります)。
  書き込むときは MSX から外してください。

### Atari 系で使う場合

方向 (1〜4 番) とトリガ (6 番) は同じ配置です。電源は 7 番 = +5V、8 番 = GND に変わります。
2 ボタン目の配置は機種によって違います。

| ファイル | 内容 |
|---|---|
| `kicad/usb2msxjoy/usb2msxjoy.kicad_sch` | MSX 版 (FXMA108、動作確認済みの構成) |
| `kicad/usb2mdjoy/usb2mdjoy.kicad_sch` | メガドライブ版 (FXMA108、実機未確認) |

部品は KiCad 9 標準ライブラリのものを使い、PCB 用のフットプリントも割り当て済みです。

| 部品 | シンボル | フットプリント |
|---|---|---|
| U1 Pico | MCU_Module:RaspberryPi_Pico | Module:RaspberryPi_Pico_Common_THT |
| U2 FXMA108 | Logic_LevelTranslator:FXMA108 | Package_DFN_QFN:WQFN-20-1EP_2.5x4.5mm_P0.5mm_EP1x2.9mm |
| J1 D-sub 9 メス | Connector:DE9_Socket_MountingHoles | Connector_Dsub:DSUB-9_Socket_Horizontal_..._Housed_MountingHolesOffset9.12mm |
| J2 UART | Connector_Generic:Conn_01x03 | PinHeader_1x03_P2.54mm_Vertical |
| C1, C2 (0.1µF)・R1 (10kΩ) | Device:C / Device:R | 0805 |

- 回路図は `tools/kicad/gen_schematics.py` で生成しています。KiCad で直接編集してかまいませんが、
  スクリプトで作り直すと上書きされます (`.kicad_pro` は上書きしません)。
  作り直す場合: `python3 tools/kicad/gen_schematics.py <KiCad の symbols ディレクトリ>`
- `tools/kicad/check_schematic.py <.kicad_sch>` で接続 (ネットリスト) を確認できます。
- FXMA108 は 0.5mm ピッチの WQFN なので手はんだは難しめです。基板を発注するなら実装サービスの利用も検討してください。
- 回路図は FXMA108 のチップを基板に直接載せる前提で、C1・C2 (パスコン) と R1 (/OE プルアップ) を描いています。
  秋月の AE-LLCNV8-DIP20 モジュールを使う場合、これらはモジュールに載っているので C1・C2・R1 は不要です。
- D-sub の取付金具 (シェル) は未接続にしています。GND に落とす場合は回路図で J1 の PAD を GND につないでください。

## ビルド

```sh
mkdir build && cd build
cmake -DPICO_BOARD=pico -DJOY_TARGET=MSX -DOUT_MODE=2 ..
make -j
```

| 指定 | 値 |
|---|---|
| `PICO_BOARD` | `pico` / `waveshare_rp2040_zero` |
| `JOY_TARGET` | `MSX` (→ usb2msxjoy.uf2) / `MD` (→ usb2mdjoy.uf2) |
| `OUT_MODE` | `0` = 74LVC07A・ダイオード、`1` = NPN / MOSFET、`2` = FXMA108 |

`PICO_SDK_PATH` を設定していない場合は `~/dev/pico-sdk` を使います。
BOOTSEL を押しながら PC につなぎ、uf2 をコピーすれば書き込み完了です。
ビルド済みのファイルは `firmware/MSX/` (MSX 用) と `firmware/MD/` (メガドライブ用) にあります (`<名前>_<ボード>[_fxma108].uf2`)。

## デバッグ

ネイティブ USB はホストに使っているので、ログは UART0 (GP0=TX, 115200bps) に出ます。
パッドをつなぐと VID:PID と、解析できた軸・ハットの情報が表示されます。

オンボード LED (GP25) で接続の段階が分かります (Pico W の LED は非対応)。

| LED | 状態 | 疑う場所 |
|---|---|---|
| ゆっくり点滅 (1秒周期) | USB 機器が電気的に検出されない | 電源 (VBUS に 5V が来ているか)・OTG アダプタ |
| 速く点滅 (1秒に5回) | 検出したがエニュメレーション失敗 | 電源不足・相性 |
| 1秒ごとに2回点滅 | エニュメレーション完了、使える HID がない | パッドの形式 (XInput など) |
| 点灯 | HID 機器を使用中 | — |

### 切り分けの手順

1. ピン確認用ファームウェア `tools/pintest/` をビルドして書き込む: LED が速く点滅し、GP2〜GP8 が 3.3V になる。Pico 本体・書き込み・測定箇所の確認用です
   (GP 番号と基板のピン番号は違います。GP2〜GP7 = 4〜7・9・10 番ピン)。ビルド済みファイルはリポジトリに含めていません。
2. 本体ファームウェアを書き込み、Pico 単体で LED がゆっくり点滅し、GP2〜GP7 が 3.3V になることを確認する。
3. VBUS に 5V を入れてパッドをつなぎ、上の表で LED の状態を見る。
4. パッドを操作して GP2〜GP7 が 0V に落ちることを確認する。
5. MSX につなぎ、BASIC で確認する:

   ```basic
   10 PRINT STICK(1); STRIG(1); STRIG(3): GOTO 10
   ```

   STICK(1) は 上=1 右=3 下=5 左=7、STRIG(1)/STRIG(3) は押下で -1。

## RP2040-Zero (Waveshare) で使う場合

使うピン (GP0〜GP8) はすべて側面のピンヘッダに出ているので、配線は Pico と同じです。

```sh
cmake -DPICO_BOARD=waveshare_rp2040_zero ..                    # 74LVC07A / ダイオード
cmake -DPICO_BOARD=waveshare_rp2040_zero -DOUT_MODE=2 ..   # FXMA108
```

- USB パッドは USB-C の OTG 変換アダプタ (C オス → A メス) でつなぎます。
- 電源: MSX の +5V (または外部 5V) は Pico の VBUS の代わりに **5V ピン**につなぎます。
  5V ピンと USB-C の VBUS が直結されていないとパッドに電源が届かないので、
  使う前にテスターで導通を確かめてください。
- オンボードの LED は WS2812 (GP16) なので、接続表示 LED は点きません。

## メガドライブ専用機 (usb2mdjoy)

同じソースから `-DJOY_TARGET=MD` でビルドする、メガドライブ 3ボタンパッド互換の専用ファームウェアです
(`firmware/MD/usb2mdjoy_pico_fxma108.uf2` など)。**実機未確認です。**

MSX とはピンの使い方が違うので、**MSX 用とは別に配線した専用機**にしてください
(特に GND が MSX は 9番、MD は 8番)。

```
Pico                FXMA108                       MD 9pin
GP2  ──────────── A0 ⇔ B0 ─────────────────────── 1  上
GP3  ──────────── A1 ⇔ B1 ─────────────────────── 2  下
GP4  ──────────── A2 ⇔ B2 ─────────────────────── 3  左
GP5  ──────────── A3 ⇔ B3 ─────────────────────── 4  右
GP6  ──────────── A4 ⇔ B4 ─────────────────────── 6  TL (A / B)
GP7  ──────────── A5 ⇔ B5 ─────────────────────── 9  TR (C / スタート)
GP9  ──────────── A6 ⇔ B6 ─────────────────────── 7  TH (本体からのセレクト信号、入力)
GP8  ──────────── /OE
3V3(OUT) ──────── VCCA
VBUS (40番ピン) ── VCCB ────────────────────────── 5  +5V
GND  ──────────── GND ─────────────────────────── 8  GND
                  A7 / B7 は未接続
```

- FXMA108 は信号の向きを自動で判別するので、TH (入力) も同じ IC で受けられます。
- 本体は TH を切り替えて数µs後に読むので、コア1 を TH の監視専用にしています (応答 0.1µs 程度)。

  | TH | 1番 | 2番 | 3番 | 4番 | 6番 | 9番 |
  |---|---|---|---|---|---|---|
  | H | 上 | 下 | 左 | 右 | B | C |
  | L | 上 | 下 | L 固定 | L 固定 | A | スタート |

- 74LVC07A で組む場合 (`OUT_MODE=0`) は、TH を 5V のまま Pico に入れられないので、
  TH → 10kΩ → GP9 → 20kΩ → GND の分圧で受けてください。
- 電源は MSX と同じく 5番 (+5V) を VBUS に入れます。
